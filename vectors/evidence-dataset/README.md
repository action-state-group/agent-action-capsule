# Dataset plans and datasets — vectors

The dataset plan of `spec/evidence-plan-ir-v0.md` §5.1 and the dataset document of §6.2.
Generated by `../../schemas/generate_dataset_examples.py`; the Python reference
(`../../schemas/check_evidence_dataset_examples.py`) and the Go gate (`go/evidenceplan`) both run
every case. Regenerate with `python3 schemas/generate_dataset_examples.py` from the repository root;
the generator is a pure function of its literal objects.

Each case is three files:

- `<name>.plan.json`: a dataset plan (`$defs/EvidencePlan` of `schemas/evidence-plan-ir-v0.json`).
- `<name>.records.json`: the committed record headers the plan runs over, in the shape a bundle
  discloses them (the `.records.json` sidecar shape of `../evidence-result/`).
- `<name>.dataset.json`: a dataset (`$defs/Dataset`). A Result's `dataset_ref` is the digest of
  this document, and its `plan_ref` the digest of the plan.

`cases.json` lists every case with `expect`: `valid`, or the reason both gates must refuse it
with. A negative names its `base` positive. It differs from that positive by one change, and the
checker confirms the base is accepted.

## The records

One book, `example-org`, over five days, plus one record of `example-org-peer`. The positive plan
`pos-window-and-exclusion` reads `example-event` and `example-run` records through seq 8, keeps
the UTC days 2026-09-02 to 2026-09-04 by `event_time_claim`, and excludes the subject
`example-org:excluded`. Its rows are seq 2, 3, 5 and 6:

| seq | record_type | event_time_claim | Row? |
|---|---|---|---|
| 1 | `example-run` | 2026-09-01T06:00:00Z | no: before the window |
| 2 | `example-run` | 2026-09-02T00:00:00Z | yes: the window's first instant |
| 3 | `example-event` | 2026-09-02T10:00:00Z | yes |
| 4 | `example-event` | 2026-09-02T23:59:59Z | no: the excluded subject |
| 5 | `example-run` | 2026-09-03T06:00:00Z | yes: a run with no event that day |
| 6 | `example-event` | 2026-09-05T01:30:00+05:00 | yes: 2026-09-04 in UTC, a day with no run |
| 7 | `example-event` | 2026-09-04T23:59:59-00:30 | no: 2026-09-05 in UTC |
| 8 | `example-note` | 2026-09-03T08:00:00Z | no: a type the population does not list |
| 9 | `example-event` | 2026-09-03T09:00:00Z | no: after `through_seq` |

A chart over these rows can tell the three kinds of day apart. 2026-09-02 was run and has one
event. 2026-09-03 was run and has none, so its count is 0. 2026-09-04 has an event but no run row,
so it was not run.

`pos-population-only` is the population node alone: seq 1 to 7. `pos-empty-window` is a window
with no record in it, so its dataset has no rows and is valid. `pos-every-predicate` adds a filter
with `equal` on a string, `one_of` and `equal` on the boolean `statement.sample` (true on odd
seq), which keeps seq 3 and 5. `pos-book-grew-past-through-seq` is the positive over the book with
seq 10 appended, a record with no canonical form (it holds a float): it is past `through_seq`, so
the plan still selects seq 2, 3, 5 and 6 and the dataset is unchanged. `pos-string-never-equals-boolean` filters on
`statement.sample` equal to the string `"true"`, which no boolean matches, so it has no rows.

## Negatives

| Reason | Cases |
|---|---|
| `rows-mismatch` | `neg-row-dropped`, `neg-row-duplicated`, `neg-rows-out-of-order`, `neg-row-past-through-seq` (seq 9 added), `neg-record-edited` (a record changed after the dataset was built, so its digest differs) |
| `plan-ref-mismatch` | `neg-plan-ref-mismatch` (another plan's digest) |
| `dataset-invalid` | `neg-dataset-extra-member`, `neg-row-carries-a-value` (a row is a ref, never a value) |
| `field-missing` | `neg-window-field-missing`, `neg-later-predicate-field-missing` (the first predicate fails, and the record is still refused for lacking the second's field) |
| `field-type` | `neg-window-field-not-a-timestamp`, `neg-window-field-without-offset`, `neg-window-field-leap-second`, `neg-filter-field-not-a-scalar`, `neg-filter-field-null` |
| `plan-shape` | `neg-filter-before-population`, `neg-filter-skips-the-window`, `neg-mixed-operator` (a `decision.resolve_verdict` node), `neg-node-contract-differs` |
| `plan-invalid` | `neg-population-without-params`, `neg-predicate-number`, `neg-field-path-trailing-newline`, `neg-window-day-impossible` (2026-09-31), `neg-window-reversed`, `neg-contract-ref-ecma-whitespace` (U+FEFF, whitespace as JSON Schema's ECMA-262 patterns read `\s`) |
| `records-invalid` | `neg-record-seq-twice` |

`../evidence-result/pos-example-org-dataset-result.json` is a Result whose `plan_ref` and
`dataset_ref` name `pos-window-and-exclusion`'s plan and dataset.

`EXAMPLE-ORG` is the synthetic placeholder throughout; no fixture names a company.
