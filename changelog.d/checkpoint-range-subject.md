- **Breaking** for readers of the unposted Evidence Request -03: the ranged checkpoints subject is now its own subject form, `checkpoint_range` with content `[a, b]` (`spec/draft-mih-agent-evidence-request-03`, §3.1 and §8.1.3), and `checkpoints` is again only the content-free form, exactly as posted in -02. A list of the forms a responder answers names each by its own token, so a responder whose full checkpoint list outgrows one answer stops listing `checkpoints` and still lists `checkpoint_range` and the history cards; the Privacy Considerations note what that tells a reader. `{"checkpoints": [a, b]}` is now `request_malformed`. The released Python 0.17.0 and 0.18.0 and Go 0.22.0 and 0.23.0 readers accept `{"checkpoints": [a, b]}` and reject `{"checkpoint_range": [a, b]}`; upgrade them together. Python adds `SUBJECT_CHECKPOINT_RANGE` (`SUBJECT_FORMS` stays the six of the -02 registry); Go adds `SubjectCheckpointRange` and drops `Subject.Ranged`. `vectors/evidence-request/checkpoints-range.json` is rewritten with the new token and two more MUST-reject request cases (`neg-checkpoints-content-range`, `neg-checkpoint-range-null`).
